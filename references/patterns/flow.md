# パターン: flow

番号付きのステップが線の上に並び、線に沿って光が流れます。ステップをクリックすると、その詳細が下に出ます。焦点のステップ（既定は最後のステップ）は、詳細が虹色の枠の中に出ます。

一本道の手順に使います。リリースの手順、オンボーディング、障害の時系列などです。

## Spec

```json
{
  "pattern": "flow",
  "title": "変更が本番に届くまで",
  "steps": [
    {"label": "ブランチ", "detail": "feature ブランチで作業する。main はいつでもデプロイできる状態に保つ"},
    {"label": "リリース", "detail": "マージすると自動でデプロイされる"}
  ],
  "focal": 1
}
```

| フィールド | 補足 |
|---|---|
| `steps[].label` | ASCII 10文字、CJK 6文字まで。44px の円の下に入る |
| `steps[].detail` | 1〜2文 |
| `focal` | いちばん大事なステップの、0始まりの番号。既定は最後。範囲外の番号は build.py がはじく |
| `hush` | `true` にすると、焦点の手順を選んだときに、見出しとほかの手順の動きが止まり、線を流れる光が止まって1秒かけて薄くなる（パチンコのフリーズ）。文字は薄くしないので読みやすさは変わらない。派手さを足さずに焦点を作る。最初から選ばれている手順（`focal: 0`）に使うと、開いた時点で止まっているので避ける |
| `judge` | `true` にすると、手順を選ぶたびに、その手順の札（詳細の見出し）が右から横に進んで詳細欄の左端の判定ラインに収まり、ラインが1回だけ強く光って点いたままになる（音ゲーの判定ライン）。`hush` と併用すると、焦点の手順ではラインを光らせない（止まった画面を保つため）。「この手順が済んだ」という1回の区切りを見せる。横向きに動くので高さは増えない。既定は `false`（判定ラインなし） |
| `foresee` | `true`（「★ 山場」）か短い言葉。焦点の手順のラベルの下に、開く前から動かない印を付ける（パチンコの先読み）。読者に最初から「ここが大事」と分からせる。段階バッジの「高」の色を使い、★と言葉でも示す。その手順を開くと印は消え、本文に替わる。手順の幅より長い言葉は2行に折り返す（build.py が警告する）。`focal: 0` だと最初から開いているので印が見えない（build.py が警告する）。既定は `false` |
| `steps[].new` | `true`（「NEW」）か短い言葉（「追加」「変更」）。手順の丸の右上に小さく傾いた札が付く。今回変わった手順の目印で、焦点（最後に見る1つ）とは別。1つの図に3個まで。architecture の箱には付かない（線やラベルと重なるため） |

## 上限

- ステップは2〜7個（範囲外だと build.py が止まります）。4個を超えると、スマホではステップを3個ずつの行に折り返し、線を隠します。
- 印刷と PDF では、焦点のステップの詳細だけを表示し、その円を強調します。
